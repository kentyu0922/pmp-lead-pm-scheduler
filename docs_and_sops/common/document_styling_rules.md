# 🛠️ 交付文档与专业排版样式规范 (Document Styling Rules)

> **适用范围**：`pmp-lead-pm-scheduler` 生成的所有分析报告、进度计划说明书、C-Suite 高管汇报摘要、排程导览（Markdown/HTML/PPTX）及 SOP 规范文档。  
> **核心目标**：统一工程交付语言，确保排版风格专业、严谨、权威，达到跨国企业（MNC）、国内大厂及政府建管部门可直接审计与汇报的工业级标准。

---

## 1. 语言与工程术语规范

1. **客观、精确的 PMP 工程自然语言**：
   - 严禁使用口语化、模糊缩略语或推测性用词（如“大概几天”、“搞定”、“差不多”）；
   - 使用规范的工程管理术语：如「关键路径 (Critical Path)」、「总浮时 (Total Float/Slack)」、「先行任务与后续任务 (Predecessor/Successor)」、「隐蔽工程验收 (Concealed Acceptance)」、「界面移交 (Handover)」、「竣工联合验收备案 (Joint Completion Acceptance & Filing)」；
2. **工期表达与日历纪律**：
   - 所有工期必须明确区分**「工作日 (Workdays)」**与**「日历日 (Calendar Days)」**；
   - 严禁出现小数天数，现场施工排期一律按**整数工日**计算；
   - 施工日历严格遵循 7×8 连续作业（春节至元宵除外），政务审批与设计招标严格遵循法定 5×8 工作日日历。

---

## 2. Markdown 结构与排版规约

1. **结构层级清晰**：
   - 每篇文档必须拥有唯一的最高一级标题（`#`）；
   - 章节层级严格遵循 `#` -> `##` -> `###` -> `####`，禁止跨级使用（例如从 `#` 直接跳到 `###`）；
2. **表格与对比矩阵规范**：
   - 大量采用标准 Markdown 表格整理多维度工程数据，表格表头必须包含明确的对齐属性（`:---` 居左，`:---:` 居中，`---:` 居右）；
   - 关键指标、责任人和时限必须独立成列，提高信息扫描效率；
3. **流程图与工序逻辑表达**：
   - 复杂的工序穿插必须配有清晰的 ASCII / Unicode 文本流向图或 Mermaid 流程图，直观展现并行、交错与前后置逻辑。

---

## 3. GitHub Alerts 警示规范

为了在文档中突出强调关键红线、法律法规及高危风险，必须合理、严谨地使用 GitHub 风格警告框，禁止连续堆叠或非法嵌套：

> [!NOTE]
> 用于提供背景工程事实、政策出处条文、计算基准公式或补充上下文说明。

> [!TIP]
> 用于给出施工效率优化建议、双流水交叉施工技巧、集采商务折扣对冲策略等最佳实践。

> [!IMPORTANT]
> 用于强调项目不可逾越的里程碑节点、前置必备材料（如施工图审合格证、安责险保单）、责任归属。

> [!WARNING]
> 用于警示工期压缩风险、跨春节停工工人返岗波动、写字楼噪音违规可能导致的停工整改。

> [!CAUTION]
> 用于最高等级工程红线报警：未批先建（无证开工）行政处罚、单次空气检测超标强行交付、消防硬伤违规阻断。

## 4. 可点击文件超链接规约

1. **文件协议与正斜杠**：
   - 在所有 Markdown 交付报告中，引用本地文件、源代码或生成的排程产物时，必须采用标准 Markdown 超链接格式，并使用 `file:///` 协议；
   - 在 Windows 系统环境下，路径中的反斜杠 `\` 必须统一转换为正斜杠 `/`；
   - **正确示范**：`[mpp_renderer.py](file:///c:/Users/HUAWEI/Desktop/pmp-lead-pm-scheduler-v4.1-optimized/core/mpp_renderer.py)`
   - **错误示范**：`[mpp_renderer.py](c:\path\file.py)` 或 包含反斜杠导致解析失败；
2. **代码行号锚点**：
   - 当具体指涉某项函数或规则时，推荐附带行号锚点，例如 `[fold_exempt_construction_permit](file:///c:/Users/HUAWEI/Desktop/pmp-lead-pm-scheduler-v4.1-optimized/core/task_utils.py#L110-L150)`。

## 5. C-Suite 高管汇报摘要 (Executive Summary) 标准三段式

面向企业管理层（C-Suite / VP / 总经理）汇报排期成果时，文档首部必须包含极简三段式摘要卡片：
1. **核心里程碑三角**：明确标示「开工日期」、「施工许可核发日」、「物理硬装竣工日」、「最终搬迁入住日」；
2. **总工期与关键路径洞察**：列出基准日历天数、关键路径经过的刚性阶段（如机电隐蔽->封板->72h联调->二次空气检测）；
3. **Top 3 风险与对冲预案**：简明扼要列出主要工期威胁（如消防审批抽检、春节假期停工）及其对应的预先对冲手段。
